## Context
`develop` holds the repository standards work (#2, merged in #3). `main` still points at the pre-standards history and there is no tag. The owner asked for `main` to be updated.

## Goal
Ship v0.1.0: `main` equals `develop`, with a generated changelog and a signed tag.

## Scope
### In scope
- Release branch from `develop`, `CHANGELOG.md` section for 0.1.0, PRs to `main` and `develop`, signed tag `v0.1.0`.
### Out of scope
- Any code change. There is no version file to bump (the console project has no `Version` property).
- A GitHub Release page (can be created from the tag later).

## Requirements
### Functional
- FR1: `CHANGELOG.md` generated by `bin/changelog 0.1.0` from the commits, not written by hand.
- FR2: PRs to `main` and `develop` from the release branch; `main` fast-forwards to the same tree as `develop` plus the changelog.
### Non-functional
- NFR1: tag signed with the owner's key.

## Acceptance criteria
- [ ] AC1: Given the release branch, when `scripts/check` runs, then build and tests pass.
- [ ] AC2: Given `main` after the merge, when compared with `develop`, then no commit is missing.
- [x] AC3: Given `CHANGELOG.md`, when read, then the `0.1.0` section lists the standards work and the nullability fix.
